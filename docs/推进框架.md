## 二、每份说明书必须写的 8 节（缺一节，基础审查直接判"阻断"）

1. **做什么 / 不做什么**：本轮范围 + 明确推迟的内容。
2. **孩子怎么用**：从打开到结束的完整路径，每屏一个主动作。
3. **页面清单**：含异常页；原型必须一一对上。
4. **跳转表**：每一页有哪些出口、去哪里、返回去哪里；系统返回手势（从屏幕左边缘右滑）怎么处理。
5. **数据**：新增字段、存储键、旧数据怎么兼容；**必须写迁移测试**。
6. **异常处理表**：至少覆盖存不了进度、数据损坏、切后台或来电、横竖屏切换、跨午夜、连点误触、脚本出错、多个标签页同时打开。
7. **速度预算**：页面打开、切换、判题反馈各多少毫秒，怎么测。
8. **验收标准**：可测量的条目，写清用什么证据（测试输出 / 截图 / 计时）。

## 三、验收清单（第 7 门，每次都跑）

**体验**
- [ ] 横屏 932×430（iPhone Pro Max）每一页截图：无遮挡、无溢出、按钮 ≥ 56×56 点。
- [ ] 每一屏只有一个最显眼的主按钮。
- [ ] 孩子能看到的文字零术语（不出现"模块、数据、加载、错误代码"）。

**跳转**
- [ ] 按跳转表逐条点一遍，没有死路；从任何页面都能回到岛首页。
- [ ] 系统返回手势在练习中不会把孩子带出页面。
- [ ] 刷新页面后回到岛首页，进度不丢。

**速度**（Playwright 无头浏览器 + 手机实测各一次）
- [ ] 首次打开到可点击 ≤ 1 秒（本地缓存后）。
- [ ] 页面切换：点下到新页面出现 ≤ 100 毫秒。
- [ ] 判题：最后一笔或点选之后 ≤ 50 毫秒给出反馈（识别本身的时间另算）。
- [ ] 连续做 50 题无卡顿、无内存增长（开发者工具看一次）。

**异常**（每条都要有测试或截图证据）
- [ ] 说明书异常处理表里的每一行，都按"怎么触发 → 看到什么 → 进度是否安全"验一遍。

**数据**
- [ ] 旧进度（v1 / v2 存档）导入后颜色格子数一致。
- [ ] 导出 → 清空 → 导入，完全恢复。

## 四、上线规则

- 新东西只放 `v2/` 预览路径；推到 `main` 会同时更新正式版，所以推送前确认根目录 `index.html` 没被改。
- 替换正式版是单独的一步，必须 Ben 明确同意。
- 每次收尾附**白话改动说明**：改了什么、可能影响什么、怎么退回。
