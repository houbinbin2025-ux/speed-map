## 零、分工（最重要的一条）

| 谁 | 负责 |
|---|---|
| **Ben** | 说清楚**诉求和意图**（想让空空得到什么）；回答**只有他知道的事实**（空空的情况、使用场景）；在真机上观察空空并照记录表记下来；最终同意上线 |
| **AI（主会话）** | 其余全部：查成熟方案、做方案取舍、教学设计、技术选型、写文档、实现、测试、审查、验收。**不把专业选择题交给 Ben** |

只有两种情况停下来找 Ben：①方案和他的诉求、意图冲突；②缺一个只有他知道的事实。

## 一、设计原则（每个版本都要对照）

1. **学习效果优先**：练什么、练多少、什么时候复习，由系统按学习规律决定，孩子只需要按「开始今天的练习」。
2. **用成熟机制，不自己发明**：先对标被验证过的产品和研究（知识图谱、间隔重复、交错练习、先诊断定位、先理解后熟练），再动手。
3. **游戏化只做两件事**：让进步看得见（颜色、地图），给一点完成的仪式感（贴珠子）。不为好玩增加和练习无关的环节。
4. **孩子能独立用**：一屏一个主动作，界面零术语，不需要大人在旁边判对错。
5. **进度绝不能丢**：任何改版先迁移、后升级，迁移必须有测试。

## 三、说明书必须写的 9 节（缺一节，审查直接判阻断）

1. **意图与指标**：引用意图卡；本版要推动哪个指标。
2. **做什么 / 不做什么**。
3. **孩子怎么用**：从打开到结束的完整路径，每屏一个主动作。
4. **页面清单**：含异常页；原型必须一一对上。
5. **跳转表**：每页一行，写出口和返回；系统返回手势（从屏幕左边缘右滑）怎么处理。
6. **数据**：新增字段、存储键、旧数据兼容、**迁移测试**；要记录的指标数据。
7. **异常处理表**：至少覆盖存不了进度、数据损坏、切后台或来电、横竖屏切换、跨午夜、连点误触、脚本出错、多个标签页同时打开。
8. **速度预算**：页面打开、切换、判题反馈各多少毫秒，怎么测、谁测。
9. **验收标准**：可测量的条目，写清用什么证据。

## 四、验收清单（门 7，每次都跑）

**学习效果**（门 2 的模拟在真实代码上重跑一遍）
- [ ] 用真实排课代码跑模拟：正确率 100% / 85% / 70% 三种孩子，每天 10 分钟，主指标达到意图卡的目标。
- [ ] 错题不会无限积压（护栏指标）。

**体验**
- [ ] 横屏 932×430（iPhone Pro Max）每一页截图：无遮挡、无溢出、按钮 ≥ 56×56 点。
- [ ] 每一屏只有一个最显眼的主按钮；孩子能看到的文字零术语。

**跳转**
- [ ] 按跳转表逐条点一遍，没有死路；任何页面都能回到首页。
- [ ] 系统返回手势在练习中不会把孩子带出页面；刷新后回到首页、进度不丢。

**速度**（Playwright 无头浏览器 + 手机实测）
- [ ] 打开到可点击 ≤ 1 秒（已缓存）；页面切换 ≤ 100 毫秒；判题反馈 ≤ 50 毫秒。
- [ ] 连续 50 题无卡顿、内存不持续增长。

**异常**
- [ ] 异常处理表每一行按"怎么触发 → 看到什么 → 进度是否安全"验一遍，留证据。

**数据**
- [ ] 旧进度导入后颜色格子数一致；导出 → 清空 → 导入完全恢复。

## 五、发布规则

- 新东西只放 `v2/` 预览路径；推到 `main` 会同时更新正式版，推送前确认根目录 `index.html` 没被改。
- `main` 上每次推送由 GitHub Actions 跑 `npm test`；失败立即修复或回退。
- 替换正式版是单独一步，必须 Ben 同意；每次附**白话改动说明**：改了什么、可能影响什么、怎么退回。
