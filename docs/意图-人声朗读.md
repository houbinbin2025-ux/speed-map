# 意图卡 · 人声朗读（门 0，2026-11-09）

## Ben 的原话
「将语音改成调用 gemini 的语言模型。」→ 看过两条路后选「按预生成做」（11-07）。
11-09 Ben 再次确认：「按 11-07 预生成」——覆盖 11-06「朗读暂不换」。

## 我理解的诉求
题目朗读现在用的是系统语音，声音机械；iPhone 静音模式下网页还念不出来（11-06 真机确认）。Ben 要的是**自然的人声**，让空空听题像有人在读给他听。
11-06 否掉的预录人声，否决理由是「约 6600 条、100–160MB，太大太重」。这次的做法是**体积换算法**：压成低码率语音、点到哪句才下载哪句，不再整包下载。

## 和硬约束的关系
| 硬约束 | 怎么守 |
|---|---|
| 0 后端、0 成本 | Gemini 只在**本机生成时**调用一次，孩子用的时候不联系任何接口；网页仍是纯静态 |
| 离线可用 | 念过的句子浏览器会缓存；没下载过、没网、或没生成音频的句子，**自动回到系统语音**，不会点了不响 |
| 不加外部依赖 | 只用浏览器自带的 `<audio>`（音频播放），不引入任何库 |
| 进度不能丢 | 不碰存档 |

## 指标
- **主指标**：空空主动点喇叭的次数（`habit.say`，已在记录）比换之前 2 周不下降，题干读错（数字、单位读错）0 条。
- **护栏**：①首页加载体积不增加（音频按需下载）；②点喇叭到出声 ≤ 1 秒（4G 网络）；③没音频的句子 100% 回到系统语音。
- **先行指标（2 周内看）**：Ben 真机抽听 50 条，读错 0 条、Ben 觉得「像人在读」。

## 最大风险（门 2 要逐条验证，不过就换方案）
1. **Gemini 读题读错**：数字、「□」、单位、英文里的数（如 3 times）读错。→ 50 条抽样全听，配读法提示；不行就换音色或模型。
2. **iPhone 上放不出来**：网页 Opus 音频（WebM）在 iOS 上的支持要真机确认；不行就改成 AAC（m4a），体积大约多一半。
3. **静音模式仍然不响**：`<audio>` 播放在静音开关下能否出声要真机确认（这是这次顺带要解决的老问题）。
4. **体积**：✅ 实测 16kbps Opus，4.7 秒的一句 11KB；全量 7754 条（中文 3877 + 英文 3877）🔍 推算 80–90MB，放在 GitHub 仓库里，一次只下一句。

## 不做
- 思维地点里随数字变化的朗读（组合太多，没法预生成）→ 继续系统语音。
- 孩子用的时候实时调 Gemini（要后端、要钱、要联网，违反硬约束三）。
