## 1. 意图与指标
- 诉求：题目朗读从机械的系统语音换成自然人声；顺带解决 iPhone 静音模式下网页念不出来（11-06 真机确认）。
- 主指标：空空点喇叭次数（`habit.say`，已有）换后 2 周不低于换前 2 周；题干读错 0 条。
- 护栏：①首屏下载增加 ≤ 4KB（只有 `voice.js` 本身）；②点喇叭到出声 ≤ 1 秒（4G）；③拿不到音频的句子 100% 回到系统语音，不出现「点了没声」。
- 先行指标：Ben 真机抽听 50 条，读错 0 条，Ben 认可「像人在读」。

## 2. 做什么 / 不做什么
**做（第一期）**
1. 题目页喇叭、示范卡喇叭、讲解卡（学一学）喇叭改为先放预生成音频。句子来源：三个题库的 `say` / `read`，加上 `render.js` 讲解卡 `R.CONCEPTS` 每一页的 `read || line`。
2. 音频放**仓库根目录** `voice/a/<key>.<ext>`，不放 `v2/` 里——`ios/sync-web.sh` 用 `git archive HEAD v2` 整包打进 App，放 `v2/` 下会把约 100MB 带进 iPad。网页取音频的地址写成 `PREVIEW ? '../voice/' : 'voice/'`（页面已有 `PREVIEW = /\/v2\//.test(location.pathname)`），以后 v2 替换根目录时零改动。第二期若走「App 联网取」，App 页面在 `ios/web/` 根下，要改用完整网址。文件名 = `v2/voice.js` 的 `key(lang, text)`；已生成清单 `voice/have.txt`（每行一个 key）。现有工具 `voice-gen.py`、`voice-corpus.js` 本来就写根目录 `voice/`，与此一致。
3. 中文日放中文音频，英文日放英文音频（按 i18n 翻译后的 `data-say` 算 key）。
4. 放音频时 `navigator.audioSession.type='playback'`；播完、`sayStop()`、切后台、超时改系统语音，**一律还原 `auto`**，否则之后的提示音会不管静音开关照样响。
5. **App 里不走人声**：检测到原生朗读接口 `webkit.messageHandlers.speak` 就直接走原生，不取 `have.txt`、不建 `<audio>`、零 `voice/` 请求。
6. 生成工具补齐：句子清单收 `q.read` 和讲解卡；生成脚本按门 2 选定的格式输出、统一响度；`--check` 报告缺哪些句子。

**不做**
- iPad App（`ios/`，中控的文件）第一期**不变**，继续原生朗读；`ios/` 一行不改，音频也不会进包（见做·2）。原因：整包音频约 90–130MB 要打进 App，体积问题 Ben 11-06 提过；第二期等 Ben 听完 50 条再定「打包进 App」还是「App 联网取」。
- 思维地点的朗读（随数字变化，没法预生成）、家里那一句固定话 → 继续系统语音。
- 不做背景音乐，不动 `house.js`、`gemui.js` 的提示音（分属 E、C）。
- 不做下载进度、不做「预先缓存全部音频」、不做设置开关（拿不到就自动回系统语音，家长不需要选）。

## 3. 孩子怎么用
和现在完全一样：看到题 → 点喇叭（按下就亮）→ 听到人声念题 → 念完喇叭熄灭 → 写答案。再点一次从头念；换题、离开页面立刻停。孩子看不到任何新按钮、新文字。

## 5. 跳转表
不新增跳转。行为要求：`sayStop()` 同时停掉 `<audio>`，不许出现「换了题还在念上一题」。调用点：
| 时机 | 现在 | 本期 |
|---|---|---|
| 换题 / 离开练习 `timers()` | 已调 | 不变 |
| 竖屏暂停 `pauseQ` → `timers()` | 已调（转屏即停） | 不变 |
| 思维地点退出 `stopSay` | 已调 | 不变 |
| 再点喇叭 | `sayIt` 第二行已调 | 不变 |
| 切后台 `visibilitychange` | 只在练习页、示范卡页经 `pauseQ` 停 | **改**：切到后台一律 `sayStop()`（`<audio>` 在 `playback` 下后台可能继续放） |
| 关闭题库预览 `qpX` | 不调 | **改**：关闭时 `sayStop()` |
| 返回手势关题库预览（`index.html` 返回处理里 `$('ovQ').hidden = true`） | 不调 | **改**：两处关预览收成一个函数 `closeQPreview()`，里面调 `sayStop()` |
| 系统返回手势、刷新 | 页面卸载 | 不变 |

喇叭熄灭：放人声时挂在 `<audio>` 的 `ended` / `pause` / `error` 事件上；只有一个 `<audio>`，换 src 前先停，旧句子的 `pause` 事件会晚到——所以**每次播放带序号 `SAY.n`，事件里序号不等于当前就忽略**（对应系统语音现有的 `SAY.u === u`）。系统语音仍沿用按字数估时长的定时器。

## 6. 数据
- **进度 / localStorage：不改**。不新增字段，不新增键，`speedmap.v1` 和 v2 存档都不碰 → 不需要迁移测试；回滚不涉及数据。
- **静态文件（新增，仓库根目录）**：`voice/have.txt`（约 7754 行 × 8 字节 ≈ 62KB，gzip 后约 35KB）和 `voice/a/` 下的音频（门 2 实测：WebM 一句约 12KB，全量 🔍 推算 90–100MB；若改 AAC 约 130MB）。
- **清单加载时机**：页面打开 3 秒后空闲时（`requestIdleCallback`，没有就 `setTimeout`）再取 `have.txt`，不进首屏；取不到 = 当作全部没有，全回系统语音。
- **离线**：网页没有离线缓存脚本（service worker）。断网时 `have.txt` 取不到，全部回系统语音，听过的句子也不用缓存——意图卡「念过的句子浏览器会缓存」按此更正。
- **仓库体积**：全量只生成一次，之后只增量补缺；补生成不重写已有文件。仓库超过 1GB 前报中控。32 位文件名哈希在 7754 条时撞车概率约 0.7%（估算），清单脚本撞车直接报错，换一种写法即可。
- **指标数据**：`habit.say` 已有，不改。人声 / 系统语音各占多少不存进度（不改数据结构），改用下面验收第 4 条的覆盖率脚本离线算。
- **题库改动后**：改了题面 → 新文字算出新 key → `have.txt` 里没有 → 自动回系统语音，不会念错旧题；`node tools/voice-corpus.js --check` 列出缺的句子，补生成即可。旧音频由 `--check` 列为「孤儿」，补生成时一起删。
- **回滚**：删掉页面里对 `voice.js` 的引用（或 `have.txt` 置空）即回到现在的系统语音；进度不受影响。

## 7. 异常处理表
| 情况 | 怎么触发 | 孩子看到 / 听到 | 进度 |
|---|---|---|---|
| 没网 / 文件 404 | 飞行模式点没听过的句子 | `<audio>` 报错 → 立刻改用系统语音念 | 不涉及 |
| `play()` 被拒 | iOS 判定不是用户点按（`NotAllowedError`） | Promise 拒绝 → 立刻改用系统语音念 | 不涉及 |
| 网慢 | 4G 弱信号 | 1.5 秒内没开始放 → 放弃音频、改系统语音（避免念两遍：先停音频再念）。1–1.5 秒出声的按护栏②不达标计入门 5 记录 | 不涉及 |
| 清单没取到 | 打开页面 3 秒内就点喇叭、或清单 404 | 系统语音 | 不涉及 |
| 音频解码失败（格式不支持） | 旧系统 | 同 404 处理；同一页面内连续 2 次失败后本次打开不再尝试音频 | 不涉及 |
| 静音开关打开 | iPhone 侧边开关 | 人声照常（`<audio>` 走媒体通道 + `playback`），门 2 真机确认 | 不涉及 |
| 切后台 / 来电 | 念到一半按 Home 或来电 | `visibilitychange` → `sayStop()` 停掉；回来不续念，喇叭熄灭，再点从头念 | 不涉及 |
| 横竖屏切换 | 念到一半转成竖屏 | 手机写字模式下竖屏会暂停练习（`pauseQ` → `timers()` → `sayStop()`），朗读随之停止；转回横屏再点喇叭 | 不涉及 |
| 跨午夜 | 0 点后英文日 / 中文日切换 | 下一次点喇叭按当时语言的 `data-say` 取音频 | 不涉及 |
| 连点 | 一秒内点 3 次喇叭 | 每次从头念，最终只有一个声音（同一个 `<audio>` 元素，换 src 前先停） | `habit.say` 照旧每次 +1 |
| 脚本出错 | `voice.js` 没加载 / 抛错 | `sayIt` 外层 try：回系统语音 | 不涉及 |
| 多个标签页 | 两页同时点 | 各自放；和现在系统语音一样 | 不涉及 |
| 存不了进度 / 数据损坏 | — | 与本功能无关（不读写进度） | 不涉及 |
| 回系统语音被 iOS 拦 | 音频失败发生在点按之后的异步回调里，iOS 可能不允许非点按触发的朗读 | 门 2 第③项真机测：①不解锁直接异步念 ②点按里先念空句再放音频（注意可能抢声音通道、压低人声）。都不行的退路：404 / 解码失败按「本次打开不再尝试音频」处理，下一次点按直接走系统语音，当次不出声的那一下计入异常记录 | 不涉及 |

## 8. 速度预算
| 项 | 预算 | 怎么测 | 谁测 |
|---|---|---|---|
| 首屏下载 | 增加 ≤ 4KB（只有 `voice.js`；`have.txt` 和音频都不在首屏） | Playwright 记录打开后 2 秒内的请求，不得出现 `voice/` | D 回归脚本 |
| 点喇叭 → 出声（已缓存） | ≤ 200 毫秒 | Playwright：`click` 到 `<audio>` 的 `playing` 事件；门 2 若选 AAC，Playwright 自带 Chromium 可能放不了，这项改用 WebKit 跑 | D 回归脚本 |
| 点喇叭 → 出声（4G，未缓存） | ≤ 1 秒 | Ben 真机门 5 抽 10 句，计时 | Ben（中控转达） |
| 音频失败 → 系统语音开始 | ≤ 1.6 秒（1.5 秒超时 + 余量） | Playwright 拦截音频请求返回 404 / 延迟 3 秒 | D 回归脚本 |
