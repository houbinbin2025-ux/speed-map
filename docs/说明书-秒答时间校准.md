# 说明书 · 秒答时间按空空实测校准（B 主模块，2026-11-09，v142）

> 意图卡、方案研究：`docs/意图-秒答时间校准.md`（门 0–1）。原来的秒答时间规则：`docs/说明书-秒答时间.md`、`docs/秒答时间分类-改动说明.md`。白话：`docs/秒答时间校准-改动说明.md`。
> 档位：可交付（空空每天在用）。对标：XtraMath（固定限时、「对但慢」单独记）、流利度研究（自动化 1–3 秒、按孩子自己的书写速度定标准）。

## 1. 意图与指标
Ben：「秒答，闪电秒答涉及到擅长的积分是更多的，但是很多题目都使用了同一个时间维度，容易将一些本来费时的变成时间总是不够，一些简单的，其实只是会，也显示秒答。这个要修正。」

推动的指标（上线 2 周后用 `S.ftime` 和每日统计看）：
| 指标 | 目标 | 先行看法 |
|---|---|---|
| 简单题「只是会」（每次在算）的秒答率 | 明显降（模拟 76–84% → 18–33%） | 技能的个人倍数在 0.6–1 之间、仍点亮的格子数 |
| 简单题「已熟」的秒答率 | 仍 ≥ 85%（模拟 100% → 87–91%） | 同上 |
| 难题「已熟但比估计慢」的秒答率 | 明显升（模拟 27–31% → 66–67%） | 难类技能个人倍数 > 1 的数量 |
| 难题「已熟、比估计快」 | 不变（模拟 94–97% → 94–97%） | — |
| 护栏：碎片、宝石 | 每有效分钟碎片降幅 ≤ 25%；乱猜不更好拿（C 11-09） | sim-gems：2.1–2.5 分钟一颗 → 2.1–2.6 |

## 2. 做什么 / 不做什么
**做**
1. 逐题用时（第一步，旧 B 已做）：`S.ftime[技能] = [倍数…]`，最近 10 次干净答对。
2. **倍数口径**（本次定稿）：倍数 = (实际用时 − 写字) ÷ 估计的「读题 + 想」。写字按当时测到的写字速度扣掉；读题算进来——读题题的秒答线大头是读题时间（每个汉字给 0.4 秒，19 个字的应用题光读题 7.6 秒、想 3 秒），只量「想」的话读得快慢永远调不到。
3. **秒答线**：写字 + 估计的「读题 + 想」× 个人倍数。
   - **简单类（口算卡、短题、点选、数线）只紧不松**。尺子是「空空在这一类里最快那部分的速度」：全类样本 ≥ 20 条、来自 ≥ 2 个技能时，倍数 = 全类第 25 百分位 × 2；不够时这个技能自己 ≥ 8 条就用自己的中位数 × 1.2。倍数夹在 0.5–1。
   - **难类（读题题、三四年级算式、多位笔算）只松不紧**：这个技能自己 ≥ 8 条，倍数 = 中位数 × 1.2，夹在 1–1.5。
   - **下限**：想的部分 ≥ 估计一半、且 ≥ 1 秒；读题 ≥ 估计一半。
   - 样本不够：照旧用估计值。
4. **闪电线**（C 11-09 对齐，审查 R1 后收紧上限）：写字 + 估计的「读题 + 想」× 这个技能自己的第 25 百分位，这部分夹在个人线（读题 + 想）的 0.35 到 0.6（BOLT）倍之间。上下限只作用在「读题 + 想」：口算卡的线大半是写字，整条线 × 0.6 会把想的部分压到 0.2 秒。技能自己不到 8 条但有类尺子：写字 + 个人线 × 0.6；没有任何个人数据：照旧秒答线 × 0.6。每天 20 次上限不变（C 管）。
5. 判完才记：这一题用的线只看这一题之前的样本；页面在记录前把线算好一次，判题、发奖励、「秒答要 M 秒内」都用它（审查 R1）。
6. 不记用时的作答：识别要确认（二选一）或确认后选了重写的、点选触发过「冷静一下」的那一轮、去掉写字不到 0.5 秒的（乱点、写字速度测慢了；审查 R1：这类样本会把全类尺子拉到底）。
7. 题库页（家长区）显示个人线：「…，按这一类 / 这个技能最近 N 次实测 × 倍数」。

**不做**
- 不回收已有的秒答次数、点亮、下架、碎片、宝石（只往前生效）。
- 不改老流程（Boss、秒答区摸底，`gemui.js` 的 `answerP`）的判法：不记用时，照旧估计值。
- 不显示倒计时（Ben 11-07）。
- 不改 `FAST_THINK` 估计表、不改 `K.FAST_CLASS` 类范围（类范围继续只管「新题型的估计值合不合理」）。

**和派单字面不同的一处（B 的技术决定，已告知中控）**：派单写「夹在这一类的上下限之间」。实测这会把两头的题锁死：10 以内口算卡（估计 2 秒）、分与合（3 秒）正好在类下限，一点都收不紧；30 秒的应用题、60 秒的竖式正好在类上限，一点都放不宽——恰好是 Ben 点名的两种题。所以范围改按估计值算（见 2.3）。

## 3. 孩子怎么用
没有新页面、新按钮。孩子照常答题；变化只在答完那句「这次 N 秒，秒答要 M 秒内」里的 M，以及哪些题算秒答 / 闪电。

## 6. 数据
- 新增：无新键。用第一步的 `S.ftime`（主存档顶层，可选字段，版本号不变；F 写合并、清洗，F 11-09 已同意格式）。
- 口径变化：倍数的分母从「估计想」变成「估计读题 + 想」。第一步还没上线，线上没有旧口径数据，不用迁移。
- 估计值改了怎么办（F 提的问题）：**接受偏差**。倍数分母是当时的估计；某个技能的 `FAST_THINK` 改了，旧倍数会偏，但每技能只留最近 10 条，几天就滚动换完；再加上倍数上下限（0.5–1 / 1–1.5）和下限保护，偏差不会让线失控。不清空重攒，免得改一次估计就把孩子打回估计值。
- 技能编号：用 `K.ITEM[id].skill` 查（挑战题、趣味题都登记了）；查不到的题本来就进不了答题流程。
- 迁移测试：`tests/ftime.test.js`（旧存档、往返、体积 ≤ 12KB）、`tests/ftline.test.js`（没样本 / 坏数据 = 估计值）。
- 回滚：回到 v141 以前的代码，`S.ftime` 被旧代码忽略，秒答线回到估计值；进度、格子不受影响（只往前生效，从不改已有颜色）。

## 7. 异常处理
| 情况 | 处理 |
|---|---|
| `S.ftime` 不是对象 / 数组里有坏值 | 判线时过滤（非有限正数、> 10 倍不算），等于没样本 → 估计值；写入时顺手洗（`E.noteThink`） |
| 某次走神很慢（> 10 倍） | 不记 |
| 写字速度测得不准 | 去掉写字不到 0.5 秒的不记；倍数下限 0.5、想的部分 ≥ 1 秒，不会把线压到够不着 |
| 识别确认、看提示、再来一次、口答 | 不记 |
| 跨午夜、切后台、多标签 | 和原来一样（用时本来就这样量；样本随每题存档） |
| 脚本出错 | 判线是纯函数，出错走全局「卡住了」兜底；无新异步 |

## 8. 速度预算
判线每题多一次扫 `S.ftime`（约 141 技能 × 10 条），实测 R2-B17 排课速度测试单独跑 72–171 毫秒 / 460 题（≤ 10 毫秒 / 题）通过。
