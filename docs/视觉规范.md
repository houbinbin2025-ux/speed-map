### 2.3 孩子看到的字：真机物理大小下限（必须，Ben 11-09）

按**真机上显示出来的大小**算，单位是 iOS 的 pt（iPhone 和 iPad mini 1pt ≈ 1/163 英寸，iPad Pro 11 ≈ 1/132 英寸、更大）。手机和 iPad 的最坏情况都是 1 CSS px = 1 pt（见下面换算），所以下限直接就是 CSS px。

| 档 | 下限 | 管什么 | 依据 |
|---|---|---|---|
| 题目 | **22pt** | 要算、要比、要写的东西本身：主算式（`.eq`、秒答 `#q`）、选项卡（`.pickcard`）、竖式格里的数字、思维页的算式和目标数 | Apple HIG Title 2 = 22pt；低年级读物 18–24pt |
| 正文 | **17pt** | 说话的句子：题干、讲解、提示、弹窗说明（`.why`、`.whysay`、`.nbsay`、`.nbthink`、`.qnote`、`.dfoot`、弹窗 `.fwcard span` 等一律算正文），其他地方的句子 | HIG Body = 17pt（系统默认阅读字号） |
| 按钮 | **17pt** | 按钮上的主文字 | HIG Body / Headline = 17pt |
| 说明 | **15pt** | 短标签、小标题、题签、按钮里的副标题、图里的文字标注 | HIG Subheadline = 15pt |
| 角标 | **13pt** | 1–4 个字符的数字和符号：计数、碎片数、+N、图里的刻度 | HIG Footnote = 13pt；HIG 最小 11pt 只给大人用 |

**怎么判一段字属于哪一档**（`tools/e2e/fontsize.py` 的 `tierOf` 和 `v2/index.html` 的 `txtFloor` 是同一套，改一处必须同时改另一处）：
1. 在题区里、属于上表「题目」那几类 → 题目。
2. 按钮本身或按钮里的粗体主文字 → 按钮（按钮里加粗的 1–4 位数字算角标，例：炉子按钮上的「4」）。
3. 1–4 个字符的纯数字和符号 → 角标。
4. 在上表「正文」列出的说话位置里 → 正文（不管多短）。
5. 按钮里的其他小字、题签和小签（`.qtag`、`.chip`、`.zsk`、`.mq`、`.dcap`）→ 说明。
6. 其余看文字：中文 ≥ 9 字、或英文 ≥ 6 个词、或带中文句读（，。？！；）、或以 . ? ! 结尾 → 正文；否则 → 说明。

> 11-10 修正（审查 R1）：11-09 初版这张表写的是「题干、讲解卡正文 22pt」「正文 = 中文 ≥ 6 字或英文 ≥ 4 词」，和审查脚本实际用的口径对不上。定稿：22pt 只给要算的东西本身；题干和讲解是阅读用的句子，按 HIG 正文 17pt；第 6 条的字数口径是为了不把名字和短标签（如「Adding to 7 and 6」「两位数减一位数 · 不退位」）当成句子，同时用第 4 条把讲解、题干这些说话位置固定为正文，避免短句漏网（例：讲解「10 less: 1 less ten, same ones」）。

**换算**（CSS px → 真机 pt）：
- 手机网页：1 CSS px = 1 pt（视口 = 设备宽，`initial-scale=1`）。
- iPad App：网页按「932 ÷ 界面大小」的宽铺满屏幕（`ios/App/App.swift`），1 CSS px = 屏幕点宽 ÷ 网页宽。

| 设备 · 界面大小 | 网页宽 | 1 CSS px = | 14px 的字 |
|---|---|---|---|
| iPad Pro 11（空空用的，1194 点宽）· 100% | 932 | 1.28 pt | 18 pt |
| iPad Pro 11 · 80%（**新的最小档**） | 1165 | 1.02 pt | 14.3 pt |
| iPad Pro 11 · 60%（11-09 前空空在用，**已去掉**） | 1553 | 0.77 pt | 10.8 pt |
| iPad mini（最小设备，1133 点宽）· 100% / 90%（最小档） | 932 / 1036 | 1.22 / 1.09 pt | 17 / 15.3 pt |
| 手机网页 | 设备宽 | 1 pt | 14 pt |

- **界面大小只给不把字缩到比手机还小的档**（11-09 起）：App 只列「网页宽 ≤ 屏幕点宽」的档，也就是 1 CSS px ≥ 1 pt。iPad Pro 11 = 100/90/80%，iPad mini = 100/90%；存过更小档的自动按最小可用档。这样**手机上达标的字，在 iPad 的任何档都达标**，标准只用按 CSS px 守一套。做法对标 iOS「显示缩放」：系统只有标准 / 放大两档，从不把界面缩到比 1:1 还小，字号由「文字大小」另外管。
- 显示字号 = CSS 字号 × 页面里的实际缩放：`fitBody()` 把题面整体缩小、思维页整页 `fit()`、SVG 图的 viewBox 缩放都会把字压小，**量的是缩完以后的**。

**只保证横屏**：iPad 竖屏时屏幕点宽只有 834，同样的档位每 1 CSS px 不到 1pt（100% 档约 0.89pt）。App 和网页都按横屏设计（竖屏出「把屏幕横过来」提示，见 5.1），竖屏不在这个标准里。

**iPad 的 WebKit 和 Chromium 不一样**（11-10 模拟器实测）：CSS `zoom` 在 iPad 上只缩盒子、**不缩网页文字**（SVG 图里的字会缩）；`getBoundingClientRect`、`getScreenCTM` 不含 zoom。所以页面里推算显示字号统一用「读到的字号 × 自己和各级祖先的 zoom、transform」（`effScale`、`svgScale`），不用这两个接口。`fitBody()` 的整块缩小在 iPad 上本来就缩不了字，只缩了盒子。

**规则**
- 必须：英文日放不下时先改排版（换行、加宽、两行按钮、收起次要信息），**不许把字缩到下限以下**；整体缩放（`fitBody`、`fit()`、SVG 压紧）缩完也不许低于下限。
- 必须：家长区（含进家长区前的锁屏 `#pinOv`）、题库、崩溃页、测试条不在这个标准里（大人看，最小 12px）。
- 新元素先按上表定字号：C 的锻造提示条 `#gemToast` 和侧栏「今天还可进入 N 次」`#forgeLeft`（`mod-c-forge5`，还没上 main）都是句子：`#gemToast` 17px；`#forgeLeft` 在会被整体缩小的锻造侧栏里，设计 20px（缩完约 17pt）。11-09 已按这个合入。
- 自动把关：`python3 tools/e2e/fontsize.py . <输出目录>` 按手机（667×375）和 iPad App（932 宽、屏幕 1194×834，按最小档 1 CSS px = 1 pt 算）× 中文和英文，量所有题型和走查脚本走过的每一屏，低于下限就列出来，结果必须是 0。每个走查脚本登记了「必须量到的页面」（如 e2e-qsum → 结算页、demofit → 示范卡），没量到 = 判不通过；新加走查脚本进 `GUIDES` 时一起登记。
- 图里的字放大（`fitSvgText`）：放大后图往四边扩到装得下；数字和后面的单位（「12 cm」「8 in all」）不拆成两行；给图框加高只在题面左栏（`#qBody`）里做，示范卡、iPad 竖式这类外层限高的地方不加（11-10 审查 R2：示范卡被撑出空白）。

## 4. 像素风

- 像素画用 canvas 逐格画，CSS 必须加 `image-rendering:pixelated`（`canvas.px` 已统一加）。缩放按整数倍最好；岛按屏幕高度放大（`world.js` `P = H / 110`），不是整数倍，是现状，可以接受。
- 所有角色、怪物、道具、贴图**原创**，用代码里的字符矩阵（`world.js` `sprite()`）或矩形表（`house.js` `list()` / `r()`）画，不放图片文件。名字口径见第 7 节。
- 描边：按钮、面板、卡片统一 2–3px 纯黑实线。不加圆角（像素格必须方），不加渐变、发光、模糊阴影；立体感只用「下方实心黑影」（`box-shadow:0 5px 0 #000`）和「方块压暗一格」。
- 动画：短、实（跳一下、掉下来、闪一下），时长 ≤ 0.5s；`prefers-reduced-motion` 时关掉（`index.html` 第 227 行已有）。
- 图标只讲一件事，纯色块，不把场景缩进图标（10-29 方向 D 被否的教训，品牌规范 §开头）。

- 必须：手机横屏（视口高 < 560px）上次要的明细要收起，点开再看；被裁掉半截的按钮比收起更糟，宁可收起。例子：结算页的碎片明细和碎片按钮收成一行「这次的碎片 +N」（2026-11-08，捣蛋鬼 1-12；锻造台在岛上也进得去）。
- 默认：练习页 = 左题右写字板；题太大时 `fitBody()` 整体缩小（最小 0.5 倍），不裁不叠。
- 默认：固定设计尺寸的页面整体等比缩放（思维页按 860×360 设计，`thinking.js` `fit()`，最多放大 1.7 倍）。左右留白按 `--padL / --padR` 的真实像素算（CSS 变量是 `max(16px, env(...))`，不能直接 `parseFloat`，要量出来）。iPad 4:3 屏上下会留空带：试过把题区拉高，结果只是在选项和底部按钮之间多出一块空白，孩子要多找一眼，所以不拉（11-08 E-5）。
- iPad：宽屏专用版面只在 `screen` 短边 ≥ 700 时打开（竖式 `vertOn()`，B 模块）。E 模块的页面（岛、家、思维地点）iPad 和 iPhone 用同一套版面，靠缩放。
