# 说明书 · 小数加减写完整得数（捣蛋鬼第 1 轮第 4 条）

> 现状：`speed:g12:dec`（一位小数，180 道）、`speed:g14:dec2`（两位小数，180 道）题面写成 `6.6 + 7.7 = 14.□`、`6.73 − 2.91 = 3.□2`，整数部分和其他位都替孩子写好了，只考一个数字。进位到整数、向整数借位恰恰是小数加减最容易错的一步。
> 改成：题面只给算式 `6.6 + 7.7 =`，孩子写完整得数 `14.3`。

## 一、题池（A）
| 题型 | 范围 | 剔除 |
|---|---|---|
| `speed:g12:dec` 一位小数加减 180 道 | 两个数都在 1.1–8.9，加减各半；**至少一半要过整数**（十分位满十进一、或不够减向整数借一） | 某个数是整数（`7.0`）；得数 ≤ 1（`0.8`，写 0 开头）；得数是整数（`14.0`，写不写 0 会两可） |
| `speed:g14:dec2` 两位小数加减 180 道 | 两个数在 1.02–8.99，加减各半；至少一半有进位 / 借位跨过小数点 | 得数 < 1；得数末位是 0（`3.40`）；某个数末位是 0 |

- **答案存法**：`ans` 存去掉小数点的整数（`14.3` 存 143，`3.82` 存 382），另加 `q.dp`（小数位数，1 或 2）。这样判题、秒答时间（`C.digits(143)` = 3 位）、错题集都不用改；只是**显示**答案时要按 `q.dp` 加小数点。
- 显示用一个函数：`R.ansText(q, ans)`（A 在 `render.js` 里加）→ `q.dp ? (ans / 10 ** q.dp).toFixed(q.dp) : String(ans)`。
- 孩子写「14.3」：小数点是一个很小的点，按现在的规则不算写了字，识别出「143」，等于答案 → 对。孩子漏写小数点也判对（小数点位置在两个数都是一位小数时没有难度，要考的是各位上的数）。
- 讲解句：`小数点对齐：6.6 + 7.7 = 14.3（十分位 6 + 7 = 13，写 3 进 1）`，英文一并加。
- 旧错题：错题集存的是题目和答案的快照（`S.mistakes[k].q / ans`），旧题照旧显示 `14.□`、答案 3，不需要迁移。

## 二、需要 B 做的（中控转）
1. **显示答案的地方都换成 `R.ansText(q, ans)`**：`index.html` 的 `answerLine`（约 1834 行）、口答「答案是 …」（约 1719 行）、描红 `ghostInk`（约 1824 行，要能画小数点）、家长区题库预览 `qpAns`（约 2133 行）。
2. **手机写字板**：确认孩子写的小数点被当成误碰忽略、不把「14」和「3」切成别的数、不弹「一格只写一个数」。真写「14.3」「3.82」各几次。
3. **iPad 蓝框（`vert.js` `BOARD` 已登记这两个题型）**：答案格里**印一个固定的小数点**（位置按 `q.dp`，在倒数第 `dp` 格前），孩子不用写点；格数按这个题型最长答案多一格的规矩不变，小数点前的格子从右往左对齐。「正确写法」也带小数点。原来的「方框夹在数字中间一格」（`2.□`）这两个题型不再用。
4. **秒答时间**（`skills.js` `FAST_THINK`）：现在是一位 6 秒、两位 8 秒（只算一个数字）。整数部分也要算，建议一位小数 8 秒、两位小数 12 秒，B 定。

## 三、上线顺序
A 的题池和 B 的显示 / 写字板 / 蓝框**必须同一版上线**：只上 A，答案会显示成「143」。所以 A 的改动放单独分支 `claude/a-dec-full`，不和别的修复一起合并。

## 四、验证
- `tests/grade34.test.js`：每道题按 `q.dp` 独立重算答案；整数部分不出现在题面；剔除规则。
- B 做完后：`e2e-vert.py` 加小数题（iPad 真写），手机真写「14.3」。
