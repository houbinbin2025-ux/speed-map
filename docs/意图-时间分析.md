## 1. Ben 的原话和我理解的诉求

Ben 原话：「要监控空空数学岛所有使用时间，后台有每天时间分析表，做一个时间使用健康度，然后好针对性优化，往有效利用时间上走。」

我理解的诉求：Ben 不缺一张时长表，他要的是**调设计的依据**：空空在岛上的时间花在哪了，多少真正在学，哪里在浪费。然后据此改排课、改奖励、改游戏时长，让同样的时间学到更多。所以页面要回答三个问题，每一项都要落到一个能调的设置上：

| 问题 | 要看到的 | 落到哪个设置（页面上每张卡写明） |
|---|---|---|
| ① 时间花在哪 | 今天、本周一共多久，分别花在：练习、错题复习、思维地点、趣味题、锻造台、空空的家、方块世界、小伙伴乐园、岛上、家长区、无操作 | 方块世界每日时长（家长区已有）；锻造台每天次数（C，现在 5 次） |
| ② 练习里有效的有多少 | 学习页面上的时间 → 真在作答 → 答对的作答（三层，见 §2）；「不会」、慢答、反复错；每 10 分钟作答几题、升档几次 | 每日练习时长（B）；难度（家长区）；讲解卡和结算页（A、B） |
| ③ 健康不健康 | 总时长合不合适；游戏和奖励玩法有没有喧宾夺主；后半段表现有没有掉；什么时段效率高 | 连续学习休息规则（C 已有：连续 30 分钟休息 5 分钟）；练习时段（家长） |

## 2. 口径：改编「学业学习时间」三层，不自造分数

对标学术里最成熟的做法：Fisher、Berliner 等人在 BTES（1972–1978，研究小学二、五年级的阅读和数学）里提出的 **Academic Learning Time（学业学习时间，下称 ALT）**。时间分三层，越往里越接近「真在学」。**下表是改编**：BTES 的「高成功率」指学生投入在自己能高比例做对的任务上，这里用「答对的作答」近似，是本项目自己的定义。

| 层 | ALT 原名 | 在数学岛里怎么算 |
|---|---|---|
| 分配时间 | allocated time | 学习页面上的时间：练习、错题复习、思维地点、趣味题，含讲解卡、答后停留、结算页 |
| 投入时间 | engaged time | 真在作答：题目出现到交卷，用现成的 `readSecs`（**不含**答对、答错后的停留），单题最多 60 秒（`SEC_CAP`） |
| 有效学习时间 | ALT（改编） | 投入时间里**答对**的那部分；其中秒答的单独标出（项目里「学会」只认秒答） |

**注意，旧数据口径不同**：已有的 `S.stats[日].sec` 是「出题到交卷 + 答后停留」（秒答 0.8 秒、慢答 2.5 秒、答错 3 秒，`index.html` 的 `fb`），还加了讲解卡（每张最多 90 秒）。它不是投入时间，页面上叫「作答（含停留）」，不和新口径混用。

**无操作怎么扣**（对标 Imagine Learning：约 60 秒没有交互就暂停计时；Khan Academy 社区答复：开着不操作、切到别的页面都不计入）。两处原文本次联网返回 403，**未核对原文**，实施前再核对。按页面分开规定，避免把「在想题」误判成无操作：

| 页面 | 不点屏幕多久之后算无操作 |
|---|---|
| 出题页（作答中） | 超过这道题的计时上限（`SEC_CAP` 60 秒）之后。这段时间本来就算在投入时间里，不重复记 |
| 讲解卡、答错后的图解、朗读中 | 讲解卡 90 秒（同 `CARD_MAX_SEC`）；图解、朗读 60 秒 |
| 其他页（岛上、空空的家、锻造台、家长区、结算页） | 60 秒 |
| 切后台、熄屏、锁屏 | 不计任何时间 |

投入时间只由新的计时模块记一份，`S.stats.sec` 照旧不动。这样不会出现同一段时间既算作答、又算无操作。

## 3. 健康度：6 项分别给档，不打总分

不合成 0–100 分（没有成熟依据，自造分数会误导）。每项单独给「正常 / 注意 / 需调整」三档。缺数据的一项给「数据不全」，不猜成正常。页面顶部写「有数据的 N 项里 M 项正常」。门槛分两类：**外部出处**的照搬，**产品设定**的标出来，上线 2 周后用真实数据校准一次。

| # | 项 | 怎么算 | 正常 | 注意 | 需调整 | 门槛出处 | 对应调整 |
|---|---|---|---|---|---|---|---|
| 1 | 每日时长 | 当天学习时间、在岛总时长（不含无操作） | 学习 ≥ 每日练习时长，且总时长 ≤ 60 分钟 | 学习不到每日练习时长；或总时长 60–120 分钟 | 总时长 > 120 分钟 | 美国儿科学会：6 岁以上不设固定上限，要「一致的限制」；总时长 120 分钟**借用**加拿大 24 小时活动指南「娱乐性屏幕时间每天不超过 2 小时」（原文只管娱乐性屏幕时间，这里拿来给含学习的总时长封顶）。60 分钟一档是产品设定 | 每日练习时长 |
| 2 | 有效学习占比 | 有效学习时间 ÷ 学习时间 | ≥ 50% | 35–50% | < 35% | 口径改编自 ALT；门槛是产品设定（学习页面里本来就含讲解卡、答后停留和结算页，正常日子约 55–60%；上线 2 周后用真实数据校准） | 难度、讲解卡长度 |
| 3 | 游戏时长 | 方块世界，对照家长设定（方块世界每日时长 + 当天加时）；小伙伴乐园单独显示，是否共用同一个每日时长等 C 确认 | ≤ 设定 | 超出不到 50% | 超出 50% 以上 | 基准取家长自己的设定 | 方块世界每日时长 |
| 4 | 岛上奖励玩法 | （空空的家 + 锻造台）÷ 学习时间 | ≤ 0.5 倍 | 0.5–1 倍 | > 1 倍 | 产品设定，依据 Ben「往有效利用时间上走」。反面案例：Prodigy 数学游戏被批评玩的时间远多于做题（只有家长个案，没有研究数据） | 锻造台每天次数 |
| 5 | 后半段表现 | 每段练习的后半段和前半段比：正确率、每题用时（`readSecs`） | 正确率降不到 10 个百分点，用时增不到 30% | 有一项超了 | 两项都超了 | 产品设定；对照已有的连续学习休息规则（`gems.js` `restAt`：连续有效学习 30 分钟休息 5 分钟） | 每日练习时长、休息规则 |
| 6 | 无操作 | 无操作时长 ÷ 在岛时间 | < 10% | 10–20% | > 20% | 判定办法见 §2；占比门槛是产品设定 | （提醒家长，不调设置） |

- 「每日练习时长」现在是排课里写死的 10 分钟（`engine.js` `BUDGET = 600`），家长区不能改；孩子点「再练一会」能再加 5 分钟。页面照实写，不写成「家长定的」。
- **只展示、不给档**：分时段效率（每小时的正确率、秒答率），回答「什么时段效率高」。攒满 14 天才显示，之前写「数据不足」。
- 删掉了原型里隐藏的第 7 条判据「正确率比秒答率高 30 个百分点 = 会做做得慢」：没有出处，而且几乎每天都会触发。

## 4. 数据盘点：已经有的和要补的

**已经有的**（旧日子能算一部分）：

| 记录 | 在哪 | 含义（照实写） |
|---|---|---|
| 每天作答秒数、题数、升档次数 | `S.stats[日].sec / n / ups` | `sec` = 出题到交卷 + 答后停留 + 讲解卡，单题封顶 60 秒；`ups` = 格子升一档的次数（任意一档） |
| 习惯记录 | `S.stats[日].h`：作答、答对、秒答、不会、熟题失误、文字题用时等 | 正确率、秒答率、「不会」占比（11-06 下午起） |
| 空空的家 | `S.stats[日].home`（`house.js` `stopClock`，每次最多 600 秒，**不判断无操作**，可能偏大） | 在家里的秒数 |
| 每日练习进度 | `S.daily`（只有今天） | 今天练了多久、预算多少 |
| 每天题数、升档（更早） | `S.log[日] = {n, ups}`（10-29 起） | 11-06 之前的日子只有这个 |
| 错题新增、学会 | `S.stats[日].mn / mp`（11-09 起） | 错题学会几道 |
| 逐题用时倍数 | `S.ftime`（v151 起） | 慢答程度 |
| 碎片 | `speedmap.gems` 的 `days[日]`：`forged` = 当天**炼出的宝石数**（不是进锻造台次数）；`fin` = 进锻造台次数（11-09 起） | 锻造台次数（11-09 起），没有用时 |
| 方块世界 | `mc_unlock.play = {day, sec}`（**只有今天**）；`mc_quest.playtime`（旧版按天记的分钟，只有 11-07） | 方块世界今天玩了多久 |

**跨设备的限制**：现在导入合并时，`S.stats` 以本机为准，只在备份里有的日子，`sec / home` 是 0，只合并了 `h`、`mn`、`mp`（`core.js importMerge`）。所以「另一台设备练的旧日子」时长不全。页面识别「有 `h`、`sec` 为 0」的日子，标「时长不全（来自另一台设备）」。

**缺的**（上线那天起记录，之前的日子标「上线前未记录」）：各活动时长、投入 / 答对 / 秒答秒数（新口径）、无操作、分时段、每段练习的前后半段、方块世界和小伙伴乐园的历史。

**新增存档字段**（方案，等中控和 F 定）：`S.time[日]`，放进度主存档，跟着导出、同步、App 副本走。

```
S.time['2026-11-10'] = {
  a: {p, r, t, f, g, h, w, k, i, s},   // 秒：练习 / 错题复习 / 思维地点 / 趣味题 / 锻造台 / 空空的家 / 方块世界 / 小伙伴乐园 / 岛上 / 家长区
  e, ok, fast,                         // 秒：投入（readSecs 之和）、其中答对、其中秒答
  idle,                                // 秒：无操作
  hr: {'19': [秒, 题, 对, 秒答], …},   // 分时段
  seg: [[开始的小时, 前半题数, 前半对, 前半秒数, 后半题数, 后半对, 后半秒数], …]   // 每段练习，最多 12 段
}
```

- 体积：一天约 0.6–1 KB，留最近 60 天，约 60 KB；读档时剪掉更早的。`S.stats` 照旧不动。
- 合并（导入、手机 iPad 同步）：每天、每项**取大**，不相加，同一份导两次不翻倍；分时段每小时每个数取大；`seg` 按内容去重取并集，最多 12 段。和错题记录、趣味题碎片同一口径。两台设备同一天都用时会少算，宁少勿重，页面口径说明里写明。
- 迁移：可选字段，版本号不变；旧存档没有就标「上线前未记录」，不补、不猜。迁移测试照前几次的清单写：旧存档、导两次、两台设备、坏值、整份替换、清空。
- 记录方式：新文件 `v2/timelog.js`（纯函数，可测）。页面每次切屏、切后台、点按时调它，它按「当前页面 + 上次操作时间 + §2 的页面上限」累计。作答那一层在交卷时记 `readSecs`。

**如果按现在这样，健康度大概是**：

1. **每日时长：11-07 要注意** ✅。作答（含停留）41 分钟。按 `fb` 估，答后停留约 14 分钟 🔍（慢答 285 × 2.5 秒 + 答错 38 × 3 秒 + 秒答 20 × 0.8 秒 ≈ 842 秒），真在作答约 27 分钟，仍是每日练习时长（10 分钟）的 2.7 倍。加上空空的家和方块世界，有记录的时长约 77 分钟（41.2 + 11.0 + 24.3），超过 60 分钟。在岛总时长没有记录 ⏳，实际更长。
2. **游戏时长：11-07 超出设定** ✅（部分）。方块世界 24.3 分钟，现在的设定是每天 15 分钟；11-07 当天的设定和加时没有记录，原因待查 🔍。
3. **岛上奖励玩法：11-07 数据不全** ⏳。只算空空的家是 11.0 ÷ 41.2 ≈ 0.27 倍；锻造台用时没有记录，不下结论。
4. **有效学习**：两天正确率都是 89%。但秒答率 11-07 只有 6%、11-08 是 45%，而 11-07 每题反而更快（6.7 秒对 8.6 秒）。**所以 6% 更可能是判定标准在变（11-07 定秒答时间、11-08 分 7 类），不能据此说空空慢**。待新数据验证，不作为优化依据。
5. **后半段表现、无操作、分时段**：⏳ 没有记录，从上线起算。

**初步结论**：现在能确定的只有一条：**11-07 练得多、玩得也多**。作答时间是每日练习时长的 2.7 倍以上，方块世界超出设定。效率高不高、累不累，要等上线后 2 周的新数据。第一批要盯的是：每天在岛总时长，以及方块世界有没有按设定走。
