## 1. 一句话

每道错题多记两样：**错了几次**（`wrongs`）和**最近 5 次出错的经过**（`hist`：哪天、写了什么、用了几秒、哪种错）。另外按技能记一份**累计数**（`S.mistStat`），因为题型错题每种只留 3 道，旧的会被删，单题上的次数会丢。每日统计加两个数（新增、过关）给「比上周好还是差」用。

**只记录，不改排课**：复习间隔、过关、`passes`、`due` 的算法一个字不动。

## 2. 新字段

### 2.1 每道错题 `S.mistakes[key]` 上（秒答格式和题型格式都加）

| 字段 | 类型 | 含义 | 什么时候写 |
|---|---|---|---|
| `wrongs` | 整数 ≥ 1 | 这道题累计错了几次（写错 + 不会） | 新进错题本 = 1；已在本里又错（练习中或复习时）+1 |
| `hist` | 数组，最多 5 条，旧的在前 | 最近几次出事的经过 | 每次 `wrongs` +1 时记一条；复习时「对但慢」也记一条 |

`hist` 每条：`{d, k, w, s, o}`

| 键 | 含义 | 取值 |
|---|---|---|
| `d` | 日期 | `'YYYY-MM-DD'`（和 `added`、`last` 同一格式） |
| `k` | 哪种 | `'w'` 写错 · `'d'` 点了「不会」· `'s'` 答对但慢（只在复习时记） |
| `w` | 孩子写了什么 | 字符串，最长 16 字；不会 / 口答 / 拿不到时为 `null` |
| `s` | 用了几秒 | 一位小数，封顶 120；拿不到时省略 |
| `o` | 口答 | 口答模式下为 `1`（家长点「答错了」，没有孩子写的内容），否则省略 |

- `w` 的写法由 B 定：手写 = 识别结果（`'22'`）；选择题 = 选中的选项文字；数线 = 点的数；竖式 = 最后一行的数。写不出就 `null`，家长页显示「--」。
- 看过提示（`peeked`）、再来一次（`retry`）、摸底、Boss 的错**不记**，和能力观察同一口径。
- 过关（`due` 变成 `null`）时 `hist` 剪到只留最后 1 条，控制体积。

### 2.2 按技能的累计数 `S.mistStat`（新的顶层键）

```
S.mistStat = { <技能 id>: {w, d, s, p, last} }
```

| 键 | 含义 |
|---|---|
| `w` | 写错次数累计 |
| `d` | 「不会」次数累计 |
| `s` | 复习时「对但慢」次数累计 |
| `p` | 过关（复习满 5 次）的错题道数累计 |
| `last` | 最近一次变化的日期 |

- 键用**技能 id**（只增不删，最稳），三种来源这样取（审查 R1 5）：
  - 新流程（`engine.js settle`）：`skillOf(inst.id).id`；
  - 秒答地图老流程（`index.html commit`）：卡片所属技能，同样经 `skillOf` 由卡片编号查；
  - 挑战题（`hardbank.js`，不在 `K.SKILLS` 里）：键用 `'hard:' + 题型编号`，家长页单独归一类「挑战题」。
- 键用技能 id 的好处：家长页要的「知识点类别」在显示时由技能映射出来，映射表归 A（`skills.js`），以后改类别不用迁移数据。
- 题型错题被 `TYPE_MIST_MAX` 删掉时，这里的数不减。

### 2.3 每日统计 `S.stats[日]` 加两个数

| 键 | 含义 |
|---|---|
| `mn` | 当天新进错题本的道数 |
| `mp` | 当天过关的道数 |

给「新增错题较上周」「本周过关」用。旧日子没有这两个数，算「--」，不算 0。

## 3. 迁移（硬约束 2：先迁移、后升级）

- **版本号不变（`v: 2`）**：全是可选字段，旧代码读到新存档会忽略，新代码读到旧存档当「没记录」。所以 v1 回滚、手机和 iPad 版本不一致时都不出错。**但会少算**：没更新的设备（比如 iPad 没装新版）上再错，`passes` 照样归 0，`wrongs` 和 `hist` 不加；导入合并后次数偏少。家长页按「至少错了 N 次」理解即可。
- **不补旧数据**：旧错题没有 `wrongs` / `hist`，显示「--」，不猜成 1（猜错了家长会误判「只错过一次」）。旧错题再错一次时从 `wrongs: 1` 开始记，并打上 `m.part = 1`，家长页对这种题标「记录不全」。
- **读档清洗**（加进 `core.upgrade`）：`wrongs` 不是正整数 → 删掉；`hist` 不是数组 → 删掉；数组里坏的条目丢掉、超过 5 条剪掉；`w` 超过 16 字截断；`mistStat` 不是对象 → 删掉；里面 w/d/s/p 不是非负整数的重置为 0（取大合并时和删掉等价，后续 +1 不会变 NaN），其他字段删掉。坏字段只丢这个字段，错题本身和排课不受影响。

## 4. 导入合并（`core.importMerge`）

原来同一道错题整条以本机为准。**11-08 改口径（C 同步分支 `mod-c-sync` 提出，F 同意）**：两边都有时整条取 `last` 更晚的那条（每次复习、再错都会更新 `last`）；**同一天的取没过关、`passes` 少的那条**（同一天有一次答错就按答错算，学习效果优先；C 审查 R2，`mod-c-sync` 2b474b9）；**晚于今天的 `last` 当今天算**（防时钟错的设备或测试模式挪后日期的数据一直胜出）；完全一样留本机。原因：手机和 iPad 互发进度后，一边已过关、一边还在复习，以本机为准会让两边永远对不上。下面说的「选中的那条」就是按这个规则选出来的。

已知小缺口：秒答下架（`engine.js sweep`）只设 `due = null; out = 1`，不更新 `last`；另一台设备上更晚复习过这道题时，会选中那边，题回到复习。下次孩子答对任一秒答题时 `sweep` 会再次下架（`S.fast` 合并取大），能自愈。要根治需 B 在 `sweep` 里同时写 `last`。

整条的 `passes`、`due` 跟着选中的那条走，新字段另外合并：

| 字段 | 合并规则 | 为什么 |
|---|---|---|
| `wrongs` | 取三者最大：本机、备份、合并后 `hist` 里 `k` 为 `w`/`d` 的条数 | 同一份备份导两次不翻倍；两台设备各错一次时，次数不会比列出的经过还少（审查 R1 4b） |
| `hist` | 两边并起来，同样内容（`d+k+w+s+o`）的条数取两边多的那边（同一天两次一模一样的「不会」算两条），按日期排序留最后 5 条；**选中的那条已过关（`due === null`）时再剪到 1 条** | 同上；过关的题合并后不再变长（审查 R1 4a） |
| `mistStat` 每个数 | 两边取大；`last` 取晚的 | 同上；和习惯记录「按天取大」一致 |
| `stats[日].mn` / `mp` | 按天取大 | 同上。**注意**：现在 `core.js importMerge` 合并 `stats` 的循环（约 419–426 行）遇到当天没有习惯记录 `h` 就跳过，实施时要改这段循环，否则只有 `mn`/`mp` 的日子合并不上（审查 R1 4c） |

整份替换（`importText`）照旧以备份为准，只过一遍清洗。

## 5. 体积

- 每条 `hist` 约 40 字节，一道错题最多 5 条 ≈ 200 字节；过关后剪到 1 条。
- 实测（T12）：460 道错题、每道 5 条满记录、300 个技能累计，整份导出 191 KB（含错题本身）。测试上限定 250 KB。Safari 单站约 5 MB。
