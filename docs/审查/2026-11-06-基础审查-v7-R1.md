## 阻断

### B1. `mergeWorld` 能刷钻石，也会丢材料、丢来源、触发重复迁移

位置：`world-core.js:325-339`；说明书 §6.2「`mergeWorld`（已写好）」、§3.3「总量……只能靠学会增加」。

| 问题 | 复现 ✅ | 结果 |
|---|---|---|
| 刷钻石块 | 证明 3 道题得 3 钻石 → 导出 → 全部合成 → 导入同一备份，重复 5 轮 | 钻石块 15 个，`bag.diamond` 仍是 3，`total.diamond` 仍是 3 |
| 钻石块没有来源 | 同上 | `gemBlocks` 从第 7 个起全是 `null`，直接打破「每一块对应一道题」 |
| 工具白拿 | 合成铁镐后导入旧备份 | 铁镐保留，铁锭 80 退回 |
| 两台设备材料丢失 | A、B 各证明 3 道不同的题 | 合并后第 3 步的题 6 道，`total.diamond` 只有 3，`gems` 只有 A 的 3 个。证明了却拿不到，违反「进度绝不能丢」 |
| 建筑丢失 | 两台设备在同一地块都盖过 | 只留当前设备的；注释写「按地块取新」，代码是先到先得 |
| `gemBlocks`、`log` 不合并 | A 有 1 个来源，B 有 2 个 | 合并后 `diamondb` = 2，`gemBlocks` 只有 1 条；`log` 丢失会让 `tempCap` 失效 |
| 同一题绑两块地 | 两台设备把相同的题绑到不同地块 | 3 道题产出 2 块永久地，破坏 1 分对 1 分 |
| 合并后不结算 | 绑定的题在另一台已全到第 3 步 | 地块仍是临时，守护题 0 道，火把照烧 |
| `migrated` 不合并 | `mergeWorld(未迁移, 已迁移)` 后再跑 `migrate` | 钻石 6 → 12，矿石 100 → 200，`gems` 12 个 |

**建议改法**：
1. 材料不存余额，改成「总收入（由证明链的 `top` 累加重算）− 总花费」。花费按事件记录并按 ID 合并，这样余额不可能超出证明。
2. `gems` 按题号取并集，由 `proof` 重建；`gemBlocks` 和已放置方块按来源题号去重。
3. `built` 按格子合并。
4. `log` 取并集。
5. `migrated` 取任一方的值；`migrate` 只允许给没有证明记录的题赋值，不覆盖已有 `s`。
6. 合并后跑一次 `settlePlots`；同题绑多块时只保留一块的绑定。
7. 把上面每一行写成迁移测试。

### B2. 题库末尾状态机卡死：一道题就能让拓地永远停止

位置：`pickBound`（`world-core.js:236-244`）、`claim` 的 `allDone`（`:253`）；说明书 §3.2「全部题都到第 3 步后，插旗直接永久」、§3.4。

- ✅ 直接复现：
  - 题库剩 2 道固定题 → `claim` 返回 `learn`（G1）。凑不够 3 分就返回空数组。
  - 还有 1 道没开放的题 → 永远是 `learn`（G2）。`allDone` 要求全部题到第 3 步，没开放的题永远到不了。手选难度的家庭会一直处在这个状态。
- ✅ 模拟实证（强孩子，每天来，180 天，`probe1.js rich`）：8 个种子的永久地块是 `166,123,119,123,124,172,119,125`，明显分成两堆。`probe2.js stuck` 里种子 2 累计被拒 79 次，第 130 天后再没有新地；卡住它的就是一道题：`look:tf:8`，`s=1`，引擎深红且已下架，又因为凑不够 3 分没有绑到任何地块，所以永远不再出现。
- ✅ 贪心算法缺陷（G4）：2 道固定题 + 2 个题型时，先拿固定题凑到 2 分，再跳过所有题型，返回空数组。单独绑一个题型明明够 3 分。
- 🔍 中等孩子后期也会走到这里；180 天的模拟只到 `s3` ≈ 250，没有跑到。
- 说明书把这段空窗写成「题不够」，真实原因有一部分是这个死锁。「15 [23] 天」是报告值，按永久地块事件算，全程最长间隔中位 37 天。

**建议改法**：
1. 剩余不足 3 分时，有多少绑多少。
2. `pickBound` 改成先按分值可行再排序，或者分别试「一个题型」和「三道固定题」两种组合。
3. `allDone` 只看当前开放且已开始的题；未开放的不挡路。
4. 补两条测试：「永远不卡 `learn`」的长跑不变量，和「已下架但未到第 3 步的题一定能回到某个绑定里」。
