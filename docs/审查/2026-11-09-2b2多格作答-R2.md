## 应修

### 1. 家长区错题分析：多格题的「正确」一栏显示成拼起来的数字
- 位置：`v2/mistview.js:72`（`ansOf` 最后一行 `return R.ansText(q, m.ans)`），显示在 `v2/index.html:2267`（`renderMistP` 的 `row`）。
- 现象：node 实测，`speed:g10:divrem2` 的「20 ÷ 8 = □ 余 □」，`MV.ansOf` 返回 `"24"`。`speed:g15:mixed` 的「46/9 = □ 又 □/9」返回 `"51"`。同一行「写的」一栏是「2 余 3」（中文，正确），家长会看到「写的 2 余 3 / 正确 24」。
- 原因：`ansOf` 不认识 `q.cells`。`R.ansText` 只处理小数，没有处理多格。开关打开后，这是唯一一个还在用 ansText 显示多格答案的地方。index.html 里其它显示答案的地方逐个核对过，都已经走了 cells：
  - 1868 口答
  - 1978 描红
  - 1993 答对整式
  - 2351 题库预览
- 建议改法：`ansOf` 在 `return R.ansText(q, m.ans)` 之前加一句 `if (Array.isArray(q.cells) && q.cells.length > 1) return R.cellsText(q, m.ans);`。家长区在 i18n SKIP 里，存中文就对。在 `tests/mistview.test.js` 补一条：多格错题的 ansOf 等于「2 余 4」或「5 又 1/9」。mistview.js 不在 B 的文件里，要先报中控（错题分析可能归 F）。

### 2. 普通蓝框靠左写时，两可笔迹不按答案定夺（既有问题，不是本轮引入）
- 位置：`v2/vert.js:258`（`want` 不是多格的分支 `String(p.ans).padStart(n, ' ')`），调用方在 `v2/index.html:1764`。
- 现象：R1 第 2 条只修了多格。普通蓝框（fill / word / fig / step）的 `judge` 接受靠左写，捣蛋鬼第 1 轮 P1 就是这么定的。但定夺仍然只按靠右给期望值。全题库模拟：靠右写的 9523 道全部能定夺。靠左写时，58 个 BOARD 题型的每一道（divrem2、mixed 除外）都定夺失败，例如 dock:g15:age、garden:g4:pyr、speed:g14:law。
  - 例子：答案 47，3 格，孩子写在左两格。第 1 格的「4」两可（候选 9、4），`want[0]` 是空格，不在候选里，于是保留「9」，写对了也判成「94」错。
- 影响面：iPad 上 58 个蓝框题型。只会把写对的判错，不会把写错的判对。多格界面已经把 `filled` 传进 `want`，修法是现成的。
- 建议改法：在 `want` 的非多格分支里，当 `p.kind` 是 fill / word / fig / step、`!p.dp`、`!p.inNum`、`filled` 里写了的格连续且个数等于答案位数时，按写了的格对齐，其余照旧靠右。竖式（vert / mul / div）和带小数点的蓝框必须对数位，不动。在 `tests/vert.test.js` 补一条：对每个 BOARD 非多格题，`want(p, n, 靠左的 filled)` 去掉空格后等于答案，并且写了的格位置对上。
