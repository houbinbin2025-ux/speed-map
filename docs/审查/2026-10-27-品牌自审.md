## 第 1 轮发现（截图：`品牌自审截图/第1轮.png`）

1. **A 组合版英文被裁掉**：英文像素字缩到半格以后，g 的下伸部分超出画布，读出来是「KonnMath」。→ 改成中英文同一格大小、上下叠，标志放大 1.25 倍和文字块对齐。
2. **A 图形标像草莓蛋糕**：对称的四层台阶，加上淡黄、淡红、深红配色，第一眼是奶油蛋糕。→ 改成从左往右爬升的方块台阶，每块方块右下角压暗一格，读成"一块块方块"。
3. **「数」的「攵」笔画糊**。→ 重画右半边：上横 + 下面一个交叉。
4. **C 的「M」像俄文 П**（中间短竖）。→ 改成两竖 + 中间 V 字。

## 第 2 轮（截图：`第2轮-前.png` 第一次改法 → `第2轮-后.png` 最终）

- 第一次改法只给对称台阶加了方块缺口，**还是像蛋糕**（`第2轮-前.png`）。这说明问题出在形状上，加细节救不回来，所以换成斜向台阶。
- 换成斜向台阶后，读起来是「浮空岛上的方块阶梯」✅。
- 遗留风险（交给 Ben 判断，不硬磨）：
  - A 的台阶在大人眼里有一点像柱状图；
  - 11×11 像素的「数」仍然偏挤；
  - B 的字标用系统圆体，换电脑可能缺字（定稿时要把文字转成路径）；
  - C 对孩子的吸引力最弱。

## 第 3 轮 · 定稿（Ben 选 A 之后）· 通过

截图：`第3轮-实际尺寸.png`、`第3轮-导出抽查.png`

- **实际尺寸**：组合版高 48px 和 32px，中文字标高 22px，英文字标高 14px，深色、浅色底都读得清 ✅。
  - 32px 高时中文笔画只剩约 1.4px，偏细 → 规范里组合版最小尺寸从 32px 提到 40px。
- **「数」字放大 12 倍看偏挤**，实际尺寸下认得出 → 记为可选改进（12×12 重画），不在本轮硬磨。
- **导出踩坑**：第一次导出的 PNG 全是空白，因为浏览器从空白页加载本地文件被拦截了。抽查时发现，已改成先写本地网页再打开，重新导出。
  - 这个坑本该被「导出后必须抽查 16px 和 512px」这一步拦住，这次确实拦住了；脚本 `源码/export.py` 已修好。
- **导出结果**：`favicon.ico` 内含 16、32、48 三个尺寸；`png/app-icon-180.png` 是 180×180；`png/mark-512.png` 边缘清楚 ✅。
